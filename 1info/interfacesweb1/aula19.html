Aula 19: Domando o Formulário

Prevenindo recarregamentos e Validações Avançadas

O Problema do Botão vs Formulário

Nas Aulas 16, 17 e 18 construímos a "carroceria" do nosso carro: um formulário Flexbox lindo e um Dashboard Grid. Na Aula 15, criámos o motor inicial: a lógica do "Segurança". Agora, vamos unir os dois!

Mas há um problema gigante. Na Aula 15, tínhamos um <button> solto na página. No mundo real (como fizemos na Aula 17), os campos estão dentro de uma tag <form>. O problema é que, por natureza, um formulário HTML tenta recarregar a página inteira (dar F5) quando você clica em Entrar. Se ele recarregar, o nosso código JavaScript morre antes de validar a senha!

A Solução: Tirar o Poder do HTML 🚫🔄

O nosso objetivo hoje é dizer ao navegador: "Ei, não atualizes a página quando este formulário for enviado. Deixa que o meu JavaScript toma conta e avalia os dados". Este é o passo mais importante para quando formos integrar o nosso site com o Firebase (banco de dados real).

1. O Dicionário de Validação (Sintaxe)

Três ferramentas essenciais para transformar um formulário comum num sistema profissional de validação de dados:

submit (O Evento Correto)

Em vez de ouvirmos um simples click num botão, vamos aplicar o addEventListener no formulário inteiro a ouvir o evento submit. Isso permite que o utilizador faça login até apertando a tecla Enter no teclado!

event.preventDefault() (O Bloqueador)

Esta é a frase mágica. Quando colocamos isso dentro da função de submissão, impedimos a página de recarregar, permitindo que a nossa lógica do "Segurança" seja ativada no JS.

function(event) { event.preventDefault(); }

&& (O Operador "E")

Na Aula 15, validámos apenas uma senha. No mundo real, você precisa do email correto E da senha correta. O && une duas ou mais perguntas dentro do if.

if (email === "a@a.com" && senha === "123")

window.location.href (Redirecionamento)

Se a validação estiver perfeita (o login for um sucesso), usamos este comando para enviar o utilizador para outra página HTML (como o Dashboard da Aula 18).

window.location.href = "dashboard.html";

2. Prática: O Formulário Inteligente

Vamos combinar o CSS Flexbox da Aula 17 com a Lógica Preventiva de JS. Este é o código que precederá o Firebase.

<!-- =========================================================
    ARQUIVO: index.html (Formulário da Aula 17 com IDs novos)
========================================================= -->
<div class="caixa-login">
    <h2>Sistema Central</h2>
    
    <!-- IMPORTANTE: O formulário tem um ID agora -->
    <form id="form-login" class="form-flex">
        <input type="email" id="campo-email" class="meu-input" placeholder="E-mail">
        <input type="password" id="campo-senha" class="meu-input" placeholder="Senha secreta">
        
        <button type="submit" class="meu-botao">Entrar</button>
    </form>
    
    <!-- A nossa mensagem de feedback -->
    <p id="mensagem-erro" style="color: red;"></p>
</div>


// =========================================================
//  ARQUIVO: script.js (A Lógica Profissional)
// =========================================================

// 1. PESCAR O FORMULÁRIO INTEIRO (Não apenas o botão!)
const formulario = document.querySelector('#form-login');

// 2. OUVIR O EVENTO 'SUBMIT' DO FORMULÁRIO
// Repare na palavra 'evento' sendo capturada na função
formulario.addEventListener('submit', function(evento) {
    
    // A FRASE MÁGICA: Impede o recarregamento da página
    evento.preventDefault();
    
    // Pescar os valores digitados NAQUELE MOMENTO
    let email = document.querySelector('#campo-email').value;
    let senha = document.querySelector('#campo-senha').value;
    const msgBox = document.querySelector('#mensagem-erro');

    // 3. A LÓGICA DE VALIDAÇÃO DUPLA (E-mail e Senha)
    if (email === "admin@etec.sp.gov.br" && senha === "123456") {
        
        // Sucesso! Oculta a mensagem de erro
        msgBox.textContent = "";
        
        // E redireciona para a página do Dashboard (Aula 18)
        window.location.href = "dashboard.html";
        
    } else {
        
        // Erro: Se uma das duas coisas estiver errada, exibe aviso
        msgBox.textContent = "Acesso negado! Credenciais inválidas.";
        
    }
});

3. Atividade: O Inspetor de Dados

Quebre e repare o código para dominar os formulários!

1

O F5 Maldito: No JS, comente a linha // evento.preventDefault(); colocando duas barras na frente. Tente fazer o login e perceba como a tela "pisca" (recarrega) e a sua mensagem de erro desaparece instantaneamente. Depois, descomente a linha para consertar.

2

Validação Inteligente: Adicione um if extra (antes da validação da senha) para verificar se o campo está vazio: if (email === "") { msgBox.textContent = "Preencha o e-mail!"; }. Isso evitará requisições inúteis ao banco de dados depois.

3

Teste de Segurança: Em vez do operador E (&&), mude a validação para o operador OU (||). Tente fazer o login colocando o email certo, mas a senha de outra pessoa. O sistema bloqueia ou permite? Por que o operador OU é perigoso em logins?

Aula 19 concluída. O formulário não pisca e os dados estão controlados!
