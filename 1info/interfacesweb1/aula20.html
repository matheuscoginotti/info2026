Prevenindo recarregamentos e Validações de Alto Nível

O F5 Maldito e a Alfândega

Se tentarmos validar um formulário real usando apenas a lógica da Aula 15, vamos bater de frente com o comportamento teimoso do HTML: Formulários recarregam a página por padrão!

Sempre que aperta "Entrar" dentro de uma tag <form>, o navegador dá um refresh (F5) para tentar enviar os dados para algum servidor antigo. Ao fazer isso, ele mata o nosso JavaScript antes mesmo de validarmos a senha. Para usar o Firebase na Aula 30, nós precisamos de travar esse comportamento.

A Analogia da Alfândega 🛂✈️

Imagine que o Formulário HTML é um passageiro ansioso a tentar embarcar no avião (recarregar a página). O JavaScript é o agente da Alfândega.

A primeira coisa que o agente faz é gritar: "ALTO! Não embarque ainda!" (preventDefault). Depois de o passageiro parar, o agente confere se o passaporte não está caducado e se a bagagem não está vazia. Só depois de tudo validado é que ele autoriza o redirecionamento.

1. O Dicionário da Validação (Sintaxe)

As ferramentas avançadas do JavaScript para garantir que o utilizador não faça asneiras no nosso formulário:

submit e event.preventDefault()

Nós "ouvimos" a submissão do formulário inteiro, não o clique do botão. A primeira linha da função DEVE ser o preventDefault para parar o recarregamento da página.

form.addEventListener('submit', function(event) {
  event.preventDefault();
});

&& (E) e || (OU)

Operadores lógicos para testar múltiplas coisas. && exige que TODAS as condições sejam verdadeiras. || exige que APENAS UMA seja verdadeira.

if (email === "admin" && senha === "123")

.trim() (Limpador de Espaços)

Um utilizador malicioso pode tentar fazer login digitando apenas "espaços em branco". O trim() remove todos os espaços do início e do fim do texto.

let emailLimpo = emailDigitado.trim();

.length (Tamanho)

Descobre quantos caracteres existem dentro da string (texto). É excelente para obrigar a pessoa a colocar uma senha forte.

if (senha.length < 6) { alert("Senha fraca!"); }

2. Prática: O Formulário Blindado

Este é o modelo profissional exato que usaremos antes de conectar o banco de dados Firebase.

<!-- =========================================================
    ARQUIVO 1: index.html
========================================================= -->
<div class="caixa-login">
    <h2>Sistema Central</h2>
    
    <!-- IMPORTANTE: O formulário tem um ID agora -->
    <form id="form-login">
        <input type="email" id="campo-email" placeholder="E-mail">
        <input type="password" id="campo-senha" placeholder="Senha secreta">
        
        <button type="submit">Entrar</button>
    </form>
    
    <!-- A nossa mensagem de feedback -->
    <p id="mensagem-erro" style="color: red;"></p>
</div>


// =========================================================
//  ARQUIVO 2: script.js (A Alfândega de Dados)
// =========================================================

// 1. PESCAR O FORMULÁRIO INTEIRO
const formulario = document.querySelector('#form-login');
const msgBox = document.querySelector('#mensagem-erro');

// 2. OUVIR O EVENTO 'SUBMIT' (E pegar o parâmetro 'evento')
formulario.addEventListener('submit', function(evento) {
    
    // A FRASE MÁGICA: "Passageiro, pare! Não recarregue a página."
    evento.preventDefault();
    
    // Pescamos os valores e já usamos o .trim() para limpar espaços em branco falsos
    let email = document.querySelector('#campo-email').value.trim();
    let senha = document.querySelector('#campo-senha').value.trim();

    // 3. VALIDAÇÃO NÍVEL 1: Estão vazios?
    if (email === "" || senha === "") {
        msgBox.textContent = "Erro: Todos os campos são obrigatórios.";
        return; // O 'return' expulsa o utilizador da função na hora! Acaba aqui.
    }

    // 4. VALIDAÇÃO NÍVEL 2: Senha e Login Corretos? (Usando &&)
    if (email === "admin@etec.sp.gov.br" && senha === "123456") {
        msgBox.style.color = "green";
        msgBox.textContent = "Sucesso! Redirecionando...";
        
        // Redireciona o utilizador para a página do Dashboard (Aula 18)
        setTimeout(function() {
            window.location.href = "dashboard.html";
        }, 1500); // Espera 1.5 segundos para a pessoa ler a mensagem
        
    } else {
        msgBox.style.color = "red";
        msgBox.textContent = "Acesso negado! Credenciais inválidas.";
    }
});

3. Laboratório de Validação (Hardcore)

Estão a terminar rápido demais? Provem que dominam a Lógica! Resolvam os desafios abaixo no código:

1

O F5 Maldito: No JS, comente a linha // evento.preventDefault(); colocando duas barras na frente. Tente fazer o login e perceba como a tela "pisca" (recarrega) e a sua mensagem de erro desaparece instantaneamente. Descomente a linha para consertar.

2

Segurança de Comprimento: Crie um novo if para validar o tamanho da senha. Se senha.length for menor que 6, exiba o erro "A senha deve ter no mínimo 6 caracteres" e trave o acesso usando o comando return;.

3

Validação de Domínio (O Filtro da ETEC): Adicione uma regra usando o método .includes(). Se email.includes("@etec.sp.gov.br") for falso (use ! no início para negar), mostre o erro: "Apenas alunos da Etec têm acesso."

4

UX e Estilos Dinâmicos: Quando o utilizador errar a senha ou o email, além de mostrar a mensagem de erro, use o JavaScript para deixar a borda dos inputs vermelha: document.querySelector('#campo-senha').style.borderColor = "red";. Quando ele acertar, mude para verde.

5

DESAFIO BOSS (Mostrar/Ocultar Senha):

Adicione um checkbox "Mostrar Senha" no HTML. Crie um novo addEventListener (para o evento 'change' ou 'click' nesse checkbox). Quando clicado, faça um if: se a checkbox estiver marcada, mude o atributo type do campo de senha de "password" para "text". Se for desmarcada, volte para "password".
