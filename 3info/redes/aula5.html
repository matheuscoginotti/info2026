Aula 05: Métodos de Transmissão

Módulo 1 • Professor: Matheus M. Coginotti

Quando enviamos um pacote de dados pela rede, ele precisa ter um "estilo" de entrega. O roteador e o switch tratam o tráfego de formas diferentes dependendo de quantos dispositivos devem receber aquela informação. Chamamos isso de Métodos de Transmissão ou Formas de Envio.

# A ANALOGIA DA SALA DE AULA Unicast: O professor chega perto de um aluno e fala baixinho só com ele. Multicast: O professor chama um grupo de 5 alunos específicos para dar um recado. Broadcast: O diretor pega o microfone e grita no pátio para a escola inteira ouvir.

1. Unicast (Um para Um)

O Unicast é a comunicação direta entre um remetente e um único destinatário. É o método mais comum e utilizado em quase 90% de tudo o que fazemos na internet.

  • Ocorre quando você abre uma página web (seu PC solicita a página diretamente ao Servidor Web).
  • Quando você baixa um arquivo, envia um e-mail ou manda uma mensagem direta no WhatsApp.
  • O Switch, por ser inteligente, adora o Unicast. Ele entrega o pacote exatamente na porta onde o MAC Address do destino está conectado.

2. Multicast (Um para um Grupo)

O Multicast é a transmissão de dados de um remetente para vários destinatários selecionados, mas não para todos da rede. É uma forma altamente inteligente de economizar banda (velocidade).

Imagine que 50 computadores em um laboratório precisem assistir a uma transmissão de vídeo ao vivo (Streaming):

  • Se fosse Unicast, o servidor teria que enviar 50 cópias do mesmo vídeo (uma para cada PC), esgotando a rede.
  • Usando Multicast, o servidor envia apenas um pacote de vídeo. Os roteadores e switches se encarregam de duplicar esse pacote no meio do caminho apenas para as portas dos computadores que "assinaram" aquele canal.
  • Onde é usado: Serviços de IPTV, videoconferências corporativas, e protocolos de roteamento dinâmico (onde os roteadores conversam apenas com outros roteadores).

3. Broadcast (Um para Todos)

O Broadcast (Radiodifusão) é quando um dispositivo envia um pacote para absolutamente todas as máquinas daquela rede local ao mesmo tempo.

Você lembra da Aula 03? O Broadcast é vital para a rede local funcionar! Ele é usado para descobrir coisas que a máquina ainda não sabe:

  • Protocolo ARP: "Ei todo mundo, quem é o dono do IP 192.168.1.50? Me passe o seu MAC!".
  • Protocolo DHCP: Quando você conecta no Wi-Fi, seu celular grita em Broadcast: "Ei, algum Servidor DHCP pode me emprestar um endereço IP para eu navegar?".
O Perigo: Broadcast Storm (Tempestade de Broadcast)

O Broadcast não passa de roteadores (ele morre dentro da rede local / LAN). No entanto, se um administrador de rede não configurar equipamentos como os Switches gerenciáveis corretamente (ativando protocolos como o STP), um pacote de Broadcast pode ficar rodando em loop infinito entre os switches.

Isso gera uma Tempestade de Broadcast: os pacotes se multiplicam tão rápido que entopem os cabos e travam 100% o processamento dos switches, derrubando a rede da empresa inteira em questão de segundos!

E o IPv6? O Fim do Broadcast!

Como o Broadcast é barulhento, inseguro e gera tráfego inútil (todos os PCs precisam parar o que estão fazendo para analisar a mensagem do grito e ver se é para eles), o novo padrão da internet, o IPv6, aboliu totalmente o Broadcast. No IPv6, os equipamentos usam apenas configurações otimizadas de Multicast para descobrir a rede.
