Aula 07: Linha de Comando (CLI)

Módulo 2 • Professor: Matheus M. Coginotti

A maior parte dos usuários comuns interage com o computador usando janelas, ícones e cliques de mouse (a famosa interface gráfica ou GUI). No entanto, para um profissional de TI, a verdadeira potência de um Sistema Operacional é desbloqueada através da CLI (Command Line Interface) — a linha de comando.

1. Por que usar a Linha de Comando?

O terminal pode parecer assustador com sua tela preta e letras piscando, mas ele é extremamente direto. Enquanto um clique de mouse exige que o SO renderize gráficos, abra janelas e processe animações, o terminal executa ordens diretas para o Kernel com consumo mínimo de recursos.

Vantagens do Terminal no Suporte
  • Velocidade: É muito mais rápido digitar um comando do que navegar por cinco pastas diferentes.
  • Automação: Permite criar scripts para repetir tarefas chatas automaticamente (ex: criar 100 pastas de uma vez).
  • Servidores Remotos: Servidores em nuvem não possuem tela gráfica; o acesso a eles é feito 100% via linha de comando (como o SSH).

2. Comandos Básicos: Windows vs. Linux

Embora a lógica seja parecida, o prompt do Windows (CMD / PowerShell) e o terminal do Linux usam termos diferentes para realizar as mesmas tarefas de navegação:

Ação Desejada Windows (CMD) Linux / macOS (Bash)
Listar arquivos da pasta atual dir ls
Mudar de diretório (entrar na pasta) cd nome_pasta cd nome_pasta
Voltar para a pasta anterior cd .. cd ..
Criar uma nova pasta mkdir nome_pasta mkdir nome_pasta
Apagar um arquivo del nome_arquivo rm nome_arquivo

3. Comandos de Diagnóstico de Rede no Terminal

Tanto no Windows quanto no Linux, o terminal é a ferramenta número um de diagnóstico quando a internet cai ou a rede falha. Os mais utilizados pelos técnicos de suporte são:

# 1. VERIFICAR O IP DO SEU COMPUTADOR Windows: ipconfig Linux/Mac: ip a ou ifconfig Exibe o seu endereço IP atual, máscara de rede e o Gateway Padrão (Roteador). # 2. TESTAR A CONEXÃO COM OUTRO DISPOSITIVO OU SITE Comando: ping 8.8.8.8 Envia pacotes de teste para verificar se há comunicação e medir o tempo de resposta (latência). # 3. RASTREAR O CAMINHO DOS PACOTES (O "GPS" DA REDE) Windows: tracert google.com Linux/Mac: traceroute google.com Mostra cada roteador intermediário pelo qual o seu pacote passa até chegar ao destino final.
