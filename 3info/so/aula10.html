Aula 10: Virtualização e Containers

Módulo 3 • Professor: Matheus M. Coginotti

Antigamente, se uma empresa quisesse rodar um sistema de banco de dados e um site institucional, ela precisava comprar fisicamente dois computadores (servidores) separados. Hoje em dia, graças à Virtualização, podemos rodar dezenas de sistemas operacionais independentes dentro de uma única máquina física, economizando uma fortuna em hardware e energia elétrica.

1. O que é Virtualização e o Hypervisor?

A virtualização é a tecnologia que permite criar uma versão virtual de um recurso físico (como um computador completo). O software responsável por gerenciar e criar essas máquinas virtuais chama-se Hypervisor (ou Gerenciador de Máquinas Virtuais).

# OS DOIS TIPOS DE HYPERVISOR 1. Tipo 2 (Hospedado): Roda em cima do seu sistema operacional atual. Exemplo: O VirtualBox ou VMware Workstation que você instala no seu Windows para testar o Linux. 2. Tipo 1 (Bare-Metal): Instala-se direto no hardware do servidor vazio, sem sistema operacional comum no meio. É extremamente potente e usado em grandes datacenters (Ex: VMware ESXi, Proxmox).

2. Máquinas Virtuais vs. Containers (A Revolução do Docker)

Embora as Máquinas Virtuais (VMs) tenham revolucionado o mercado, elas possuem um ponto fraco: cada VM precisa carregar um Sistema Operacional inteiro dentro dela (com direito a kernel próprio, arquivos de sistema e consumo pesado de memória RAM).

Para resolver esse peso excessivo, surgiu a tecnologia de Containers (com o Docker como principal expoente mundial).

Característica Máquina Virtual (VM) Container (Ex: Docker)
O que ele virtualiza? O hardware inteiro (CPU, RAM, Placa de rede simuladas). Apenas o ambiente de software e as dependências da aplicação.
Sistema Operacional Cada VM roda um SO completo e pesado separado. Todos os containers compartilham o mesmo Kernel do SO hospedeiro.
Consumo de Recursos Alto (exige muitos Gigabytes de RAM). Extremamente leve (consome apenas alguns Megabytes).
Velocidade de Inicialização Lenta (demora minutos para dar o boot na VM). Instantânea (liga em frações de segundo).

3. Por que desenvolvedores e empresas amam containers?

O maior problema clássico da programação era a frase: "No meu computador funciona perfeitamente, mas no servidor do cliente dá erro!".

O Isolamento Perfeito

Com o Docker, você empacota o seu site ou sistema junto com todas as bibliotecas e versões exatas que ele precisa dentro de um container. Esse container pode rodar no seu notebook, no servidor da ETEC ou na nuvem da Amazon (AWS) sem sofrer alteração nenhuma, garantindo que o software funcione exatamente da mesma forma em qualquer lugar.
