Sistemas Operacionais

Aula 06: Permissões de Usuários e Grupos

Módulo 2 • Professor: Matheus M. Coginotti

Em um computador moderno — especialmente em ambientes corporativos ou servidores compartilhados —, várias pessoas podem utilizar a mesma máquina. Se qualquer usuário pudesse apagar arquivos do sistema ou ler documentos confidenciais de outros colegas, a segurança estaria arruinada. É por isso que os Sistemas Operacionais aplicam regras rígidas de Permissões de Usuários e Grupos.

1. O Superusuário (Root vs. Administrador)

Todo sistema operacional multiusuário possui uma conta especial com poderes absolutos sobre a máquina:

  • No Windows: O usuário é chamado de Administrador.
  • No Linux e macOS: O superusuário é chamado de Root.
A Regra de Ouro da Segurança

Nunca utilize o computador no dia a dia logado direto na conta de Administrador ou Root. Se você abrir um arquivo malicioso ou visitar um site infectado com privilégios máximos, o vírus terá passe livre para destruir o sistema operacional inteiro. O correto é usar uma conta comum para tarefas diárias e elevar os privilégios (pedir a senha de admin) apenas quando for estritamente necessário.

2. O Modelo Clássico de Permissões (Linux/Unix)

No Linux, a segurança de arquivos é baseada em três pilares fundamentais de permissão que podem ser aplicados a qualquer diretório ou arquivo:

Permissão Letra O que ela permite em Arquivos? O que ela permite em Diretórios (Pastas)?
Leitura r (Read) Abrir e ler o conteúdo do arquivo. Listar os arquivos que estão dentro da pasta (ver o conteúdo dela).
Escrita w (Write) Modificar e salvar alterações ou apagar o arquivo. Criar novos arquivos ou apagar arquivos de dentro da pasta.
Execução x (eXecute) Rodar o arquivo como se fosse um programa ou script. Entrar na pasta (dar um comando cd) para acessar seu interior.

3. Dono, Grupo e Outros

Cada arquivo no sistema pertence a uma lógica de três níveis de controle:

  1. User (Dono / U): O usuário específico que criou o arquivo.
  2. Group (Grupo / G): Um grupo de usuários que compartilham o mesmo projeto ou departamento (ex: equipe de suporte).
  3. Others (Outros / O): Qualquer outra pessoa que use o sistema.
# EXEMPLO DE LEITURA DE PERMISSÃO NO TERMINAL LINUX -rwxr-xr-- 1 matheus suporte 4096 Mar 19 10:00 relatorio.sh Dono (matheus): Tem permissão de Ler, Escrever e Executar (rwx) Grupo (suporte): Tem permissão de Ler e Executar, mas NÃO pode alterar (r-x) Outros: Têm apenas permissão de Leitura (r--)

4. O Comando Sudo (SuperUser Do)

Para evitar ficar logado o tempo todo como Root no Linux, os administradores usam o comando sudo antes de executar uma tarefa pesada.

Quando você digita sudo apt update, o terminal pede a sua senha pessoal de usuário comum. Se você estiver cadastrado no arquivo de administradores autorizados do sistema, o Linux te empresta os superpoderes do Root por alguns segundos apenas para aquela linha de comando específica.
